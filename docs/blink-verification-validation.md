# 眨眼校验验证记录

## 1.1.3 本轮睁眼基线及通过后抓拍（2026-09-16）

- 新录屏复现固定阈值的局限：明显闭眼时双眼 EAR 约 0.153 / 0.143，此前明确睁眼约 0.232 / 0.228；1.1.2 没有检测到 Closed。单张截图或单段回放通过不能代表真实成功率。
- 保留固定明确睁眼和闭眼规则；对过渡帧，增加本轮双眼相对睁眼基线下降至少 30%、双眼 EAR 均不超过 0.16 的闭眼路径。近两秒最多 40 个明确睁眼样本、至少三个且跨度至少 100ms，分别取上四分位值；单帧异常高值不能抬高基线，丢脸等重置会清空基线。
- 动作通过后的稳定计时改为跟踪人脸位置，眼睑再次闭合或过渡只等待明确睁眼的最终照片，不清除已经通过的动作。丢脸、多人、无效测量、明显位移、陈旧帧与整轮超时仍拒绝。
- 区分最后有效人脸帧和最后明确眼睛状态的时间。5fps 连续 Closed→Transition→Open 曾因明确状态相隔 400ms 被误当作丢帧；现在实际帧间隔仍按 350ms 限制，动作前过渡状态仍最多容忍 200ms。
- 两段录屏本机回放：新录像在约 15.172 秒通过动作、17.518 秒完成抓拍（约 8.5 秒重新开摄像头）；上一段在约 4.242 秒通过动作、5.789 秒抓拍。每段原始约 20fps 和四种约 5fps 取帧起点共十组完整链路回放均通过。录屏有缩放和重复帧，不能代替摄像头时延及普遍准确率验收。
- 临时回放测试移除；永久测试保留匿名数值和合成状态，验证相对闭眼、单眼/小幅变化拒绝、静态窄眼拒绝、基线失效、通过后的闭眼帧不能抓拍，以及真实帧间隔限制。
- 完整 Release 测试 121 项、SDK 测试 14 项通过，Vue 生产构建和 Windows 自包含发布通过；独立代码审查未发现阻断问题。单帧高值与过期基线拒绝也有永久测试。临时诊断图片与数值文件已清理，用户原始录像未改动。

## 1.1.2 连续动作修正（2026-09-16）

- 用户录屏在本机解码，截取摄像头预览区域后送入实际 YuNet / Face Mesh / BlinkCaptureTracker；约 20fps 原始回放复现旧逻辑没有 Closed 帧、无法通过校验。录屏并非摄像头原始帧，存在缩放、压缩和重复画面。
- 可见闭眼画面的双眼 EAR 约 0.1205 / 0.1162，旧 0.10 阈值将其判成 Transition。闭眼阈值修正为双眼均不超过 0.13，睁眼仍要求双眼均至少 0.16，中间区间保留为过渡；半睁眼示例 0.1461 / 0.1497 不能计为闭眼。
- 单独修正闭眼阈值后，8.134 秒通过动作，但随后被数秒前的初始位置基准重置。通过动作时更新位置基准，从当前姿态开始稳定抓拍；丢脸、多人、无效测量、长间隔和相对新基准明显移动仍重新校验。
- 两项修正后，约 20fps 全链路回放在 8.134 秒通过动作，9.681 秒完成抓拍。降采样至约 5fps，四种取帧起点均完成抓拍。
- 永久测试仅保留数值与合成状态序列，包括闭眼阈值边界、半睁眼拒绝、完整动作后稳定抓拍及位置基准更新。先验证旧实现失败，再验证修正通过。
- Release 自动测试 112 项、SDK 测试 14 项均通过；Vue 生产构建及 Windows 自包含发布成功。发布 EXE 版本为 1.1.2，模型 SHA-256 与源码一致。
- 视频与临时图像未加入仓库；临时视频诊断测试在验证后移除。仍需新版安装后的真实摄像头验收；录屏回放不代表不同人群、设备或光照下的准确率。

## 1.1.1 睁眼误判修正（2026-09-16）

- 本机使用用户提供的预览截图复现：旧 OCEC 模型将有可见眼裂的双眼判为闭眼；调整裁切和颜色通道未解决。
- 替换为本机 Face Mesh 眼睑关键点推理，按双眼眼裂纵横比区分睁眼、闭眼和过渡状态。双眼均至少 0.16 判为睁眼，均不超过 0.10 判为闭眼，其余有效值判为过渡；低置信度或无效关键点拒绝判定。
- 相同截图经 JPEG、YuNet、人脸裁切及新分类器完整链路后判为睁眼。图片仅在本机内存中处理，未加入仓库；临时诊断测试已移除。
- `scripts/build-installer.ps1`：Release 测试 105 项通过、Vue 生产构建通过、自包含发布和安装包编译成功，版本 1.1.1。
- 模型 CPU 推理测试使用有效尺寸的合成灰色人脸区域，确认实际执行模型后返回 Unknown；新增眼裂比例边界和过渡状态测试。
- 模型来源、许可证及 SHA-256 见 `FaceCaptureAgent/Models/README.md`。旧 OCEC 资源已移除。
- 静态截图回归仅证明该画面的睁眼误判已修正。升级安装、连续真人眨眼、真实闭眼、眼镜和弱光仍需实机验收。

## 1.1.0 初次验证（2026-09-15）

以下为初版验证记录，模型及测试数量以以上 1.1.1 记录为准。

## 功能范围

- Agent 自动模式新增可选 `blinkVerification`，默认关闭。
- 双眼睁开至少两个明确样本且跨度至少 100ms，随后闭眼 50–1000ms，再重新睁开至少 100ms，才进入稳定抓拍。
- 阶段时长用单调时钟。短暂过渡状态不计为明确样本，最多容忍 200ms；单个睁眼样本加过渡不能建立睁眼基线。
- 人脸丢失、多人、明显漂移、无效眼部画面及长间隔重置；整轮 15 秒超时。重拍重新校验，拍摄帧要求双眼睁开。
- SDK 在绑定 roundId 前确认眨眼要求，旧 Agent 缺失/false 回显均拒绝。组件、演示页提供提示与重试入口。
